# AGENTS.md

Shared guidance for AI coding agents working in this repository. Keep project rules here; `CLAUDE.md` and `.github/copilot-instructions.md` refer to this file. These instructions are independent of the agent model version.

## Commands

```bash
make clone-theme  # Fetch the PaperMod commit in .papermod-version (needed before the first build)
make run          # Local Hugo server with drafts and live reload
make build        # Production Hugo build with minification
make new-post     # Create a single-file post
make new-post-dir # Create a post bundle with images/
make resume       # Regenerate Japanese and English resume HTML and PDFs
```

## Site structure

- This is a Hugo site published at https://konumaru.com/ with the PaperMod theme. Posts live in `content/posts/<category>/<post>.md` or `content/posts/<category>/<post>/index.md` with local `images/`.
- `themes/PaperMod` is an ignored plain clone pinned by `.papermod-version`. Use `make clone-theme` when it is missing or the pin changes. Keep site customizations in `layouts/` instead of editing the clone or forking theme templates such as `single.html`.
- Mermaid rendering uses `layouts/_markup/render-codeblock-mermaid.html` and the loader in `layouts/_partials/extend_post_content.html`; the Mermaid version is pinned in that partial. Related and support sections use the same PaperMod hook. Keep per-page logic out of `extend_footer.html`, which runs inside a cached footer.
- Edit source in `content/`, `layouts/`, `static/`, and `resume/`. `public/` is generated by Hugo. The tracked `docs/` files are legacy site output; the deploy workflow publishes `public/`, so ordinary site changes should not target `docs/`.

## Resume

- Sources are `resume/README.md` and `resume/README.en.md`, with shared CSS in `resume/styles/markdown-theme.css`. `resume/head-custom.html` and `resume/build.mjs` control the HTML pages.
- `make resume` creates `static/resume/{index.html,resume.pdf}` and `static/resume/en/{index.html,resume.pdf}`. These files are committed and Hugo copies them into the site. After changing resume sources or styling, regenerate and inspect the affected HTML and PDFs before committing.
- On pushes to `main`, `.github/workflows/gh-pages.yml` attempts regeneration but continues on failure. A failed run can deploy old or partially regenerated artifacts, so keep committed files current and check the regeneration step. `.github/workflows/resume-reminder.yml` only opens a twice-yearly issue.

## Validation and deployment

- There is no test framework. Run `make build` after site changes; run `make resume` as well when changing the resume.
- `.github/workflows/gh-pages.yml` builds pull requests and deploys `public/` on pushes to `main`. It pins the Hugo Extended version; validate with that version when changing the pin or diagnosing a CI-only difference.
